## 一条语音是怎么出来的

```text
她看上下文，调用 speak（text、style、intensity、scene）
        ↓  qq_chat/tool_server.py：本轮授权、参数检查
qq_chat/voice.py：文字清洗、长度检查、排队（VoiceReplies）
        ↓  JSON 行协议，常驻子进程（ProcessSynthesizer）
tools/indextts_backend.py：按 style 和 scene 挑一段原声 → IndexTTS2 合成
        ↓  32 kHz 单声道 WAV
Bridge.send_audio → OneBot record → QQ 语音
```

`voice.py` 不依赖 QQ 和模型；后端不知道 QQ 目标、凭据和聊天历史，只收到要念的文字、风格、scene 和一个不透明的聊天名。换引擎只需换 `voice.command` 并遵守协议。

### 她怎么说

- `speak` 的参数：`text`（口语稿）、`style`（日常、开心、安慰、激动、压着怒气、哽咽）、`intensity`（低、中、高）、`scene`（一句话写想怎么说，只写情绪、态度和关系，不写话题）。使用规则在 `qq_chat/prompts.py` 的 `SPEAK_RULES`。
- 每段 6 到 35 字（约 10 秒），scene 最多 60 字；话长就分几次调用。群友触发的一轮最多 4 段。
- 主人会话通过终端命令 `tools/speak.py` 调用，群聊访客通过原生工具调用，两条入口共用同一套授权和队列。
- 每轮说明的第一行写着当前日期、星期和时间，她不用自己查。

### 挑原声

- 原声库在本机 `workspace/voice-library/`（yhx、role、zyqx、wmxztk 四个库），共 316 段质检通过、确定是她本人的原声。每段有一句语气说明和适合的风格标签。建法见该目录的 README。
- 先按 style 留下标了这种风格的原声；日常、开心、安慰不会用到标为重情绪的原声。
- 再打分：0.75 × scene 与语气说明的相似度 + 0.25 × 要念的话与原声台词的相似度，检索模型是 bge-m3（CPU）。最近 6 次用过的原声扣 0.01。取最高分。
- 最高分低于 0.45（没写 scene 或完全不着边）时不用原声库，改用风格预设：平和原声加情绪向量，1.15 倍速。实际使用中极少发生。

### 合成

- 引擎是 IndexTTS2 加社区的“小爱 V5”微调，装在 `~/.local/share/aemeath-voice/`，独立的 Python 环境，常驻显存约 9 GB。连上 QQ 时预热。
- 挑中的原声同时当音色、念法和情绪的参考，原速。固定种子 42，同样的输入得到同样的声音。
- 合成后把句中超过 1 秒的空白截到 1 秒。
- **`intensity` 在挑中原声时不起作用**，只在退回风格预设时有效。规则里还写着它有效，她多数时候填“低”。见待办第 3 项。

### 接着上一句走

同一个聊天里，离上一条语音 60 秒以内的下一条：

- 照常用自己挑中的原声，念法和嗓子都是它的；
- 情绪是六成自己挑的，加四成这个聊天刚才实际念出来的状态；
- 说话音量对齐到这一串的第一句，最多调 6 dB。

隔了 60 秒以上的照原样念。激动、压着怒气、哽咽不参与，原样念，并让这个聊天重新开始；没挑中原声的语音也不参与。她不用判断，speak 的参数没有变化。

## 开关

`config.json` 的 `voice`：

| 配置 | 作用 | 本机现在 |
|---|---|---|
| `enabled` | 语音总开关 | 开 |
| `mode` | `reply`：每条回复自动朗读；`tool`：她自己调 speak 决定何时说 | `tool` |
| `group_enabled` | 群聊访客可以用 speak | 开 |
| `group_voice_only` | 群聊只发语音不发文字，每轮都说 | 开 |
| `private_voice_only` | 主人私聊只发语音；私聊里发 `/voice on`、`/voice off`、`/voice` 或“切回文字”即时切换 | 由主人随时切换 |
| `preload` | 连上 QQ 就加载模型 | 默认开 |
| `timeout_seconds` | 每段合成最多等多久 | 180 |
| `debug_log` | 调优记录的目录，不写就不记 | 开，调优结束后关 |
| `command` | 后端命令和参数，见下 | |

后端命令的参数：

| 参数 | 作用 |
|---|---|
| `--library <目录>`（可重复）、`--embedder <模型目录>` | 按 scene 挑原声；两项必须同时给，库的向量必须由同一个检索模型算出，否则拒绝启动 |
| `--continuity` | 打开“接着上一句走” |
| `--continuity-window <秒>` | 多久以内算接着说，默认 60 |

只发语音的会话里，她没调 speak 时程序把最终正文按默认风格念出来；合成或发送失败时改发原文。管理命令、命令确认和失败兜底始终用文字。

**回退**：去掉 `--continuity` 两个参数并重启，回到每条各自挑原声；去掉 `--library` 和 `--embedder`，回到只按 style 的风格预设。更早的 ONNX 后端和安装方法见历史记录。

## 已知的问题

- **语气说明和风格标签不准**：它们是按剧情文字写的，没有听过。有的原声标着兴奋，实际偏低偏稳；有的兴奋的原声被标成了日常。
- **前几名分数几乎平手**：第一名和第二名通常只差 0.01，挑哪段有运气成分。她写的 scene 也很像，常带“俏皮”“笑着”。
- **大部分语音落在最活泼的一池**：约三分之二选了开心，其中多数填的是“开心、低”，而“低”不起作用。
- **缺素材**：害羞、撒娇、嫌弃、被逗得慌张这类原声很少或没有，挑选和调参都补不出来。
- **只发语音时什么都得念**：技术解释这类书面内容念出来像念稿，偶尔漏念半句。主人决定暂不处理。

## 待办

顺序是助手的建议，主人可以调整。

1. **核对原声的语气说明和风格标签，标出亢奋的原声。** 给 316 段都量音高、语速、停顿、音量，挑出说明和测量明显矛盾的，按使用次数排成一页给主人听。亢奋的标上之后默认不选。可以顺带加一个按测量定的“劲儿大小”标签。
2. **固定题库。** 从真实记录里挑 15 到 20 段典型对话，以后每个改动先自动重放、只听有变化的部分、不带提示地盲听，通过再上线。主人：先不做，记在这里。
3. **提示词和强度一起改。** style 怎么选（现在偏向开心）、让强度真正生效（试听过：平和原声当零、挑中的原声当十成，两个方向都听得出）、示例里不要求库里没有的情绪。要和爱弥斯错开改。
4. **检索。** 台词相似度占的 25% 要不要降（去掉的话约三成的挑选会变）；分数挤在一起怎么办，等调优记录攒够再看。
5. **连贯继续观察。** 60 秒窗口试用的反馈；私聊要不要把念法和嗓子锚在一串的第一句；混合比例要不要调。
6. **借其他角色的情绪补素材。** 她自己的原声之间借得过来，但情绪会带着嗓子变，要单独试。前提是主人同意用其他角色的台词。
7. **在 QQ 里直接标“这条不对”。** 现在要在终端里敲命令，一次都没用过。
8. **调优结束后**关掉 `debug_log` 并删除记录目录。

流程上的建议（助手提出，主人还没表态）：线上一次只变一项；语音配置里不含密钥的部分纳入版本管理；明确谁可以重启桥接。

## 运行和测试

```sh
python3 -m unittest discover -s tests -q
```

后端相关的测试要在语音环境里才不会被跳过：

```sh
~/.local/share/aemeath-voice/indextts-venv/bin/python -m unittest tests.test_indextts_backend
```

改 `config.json` 的语音配置后要重启桥接才生效。重启前确认爱弥斯空闲、没有在跑的任务。占显卡的实验只在她空闲时做，并限制自己这边的显存。

## 许可

“小爱 V5”整合包限个人非商用；公开展示合成音频要标明“AI 合成、非官方、非配音演员本人”。IndexTTS2 适用 bilibili 的模型使用许可协议。
